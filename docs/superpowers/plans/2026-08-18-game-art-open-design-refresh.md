# Game Art Open Design Refresh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Rework Game Art creation and browse views into an Open Design-inspired visual board without changing APIs, persistence, or generation behavior.

**Architecture:** Keep `GameArtStylePreview` as the shared presentation boundary and add explicit `mode`/display props for creation and browse contexts. Keep form state in `GameDesignSystemCreatePage` and version selection in `GameDesignSystemWorkspace`; use CSS modules for all layout and responsive behavior. Group the existing canonical specification through a local presentation map rather than changing the snapshot schema.

**Tech Stack:** React 19, Next.js 16, TypeScript, CSS Modules, Testing Library, Playwright.

## Global Constraints

- Do not change `GameArtStyleSnapshot`, API payloads, database columns, generation prompts, or immutable-version behavior.
- Keep the single locked Pixel Art v1 preset and existing image failure/legacy null states.
- Keep existing Keco light palette, typography, and accessible labels.
- Do not add dependencies or runtime asset generation.
- User requested speed over TDD; run focused regression tests after implementation.

### Task 1: Restructure shared Game Art presentation

**Files:**
- Modify: `src/components/game-design-system/GameArtStylePreview.tsx`
- Modify: `src/components/game-design-system/GameDesignSystemsPage.module.css`

**Steps:**
- Add a display mode prop with `creation` and `browse` values, defaulting to `browse` for existing call sites.
- Replace the flat 11-item specification list with four presentation groups: Visual identity, Craft, World, Production. Keep the same snapshot field values and map each field to exactly one group.
- Render a `Visual DNA` summary containing visual identity, palette/lighting, shape language, and pixel technique. Keep it before the detailed groups in browse mode and compact in creation mode.
- Add local disclosure state for groups, with Visual identity open initially. Use native buttons with `aria-expanded` and stable `id`/`aria-controls` pairs.
- Preserve the existing image failure callback and unavailable states. Render the map as the dominant frame and bound the character companion frame with a non-square responsive aspect ratio and a max-height.
- Add mode-specific class names and CSS for the visual board, summary, group navigation, disclosure groups, and customization section. Keep all selectors local to the existing CSS module.
- Verify TypeScript and focused component tests compile after the presentation change.
