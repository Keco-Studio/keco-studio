# EvalSpec Contract

Create EvalSpec before any Keco, PixelLab, or Godot write. Every implementation file serves at least one evaluation. Each evaluation names a stable ID, source requirement, deterministic preconditions, action, expected values and tolerances, evidence, pass rule, and `manualRequired` state.

Use `state` for exact values, `flow` for bounded transitions, `regression` for adjacent behavior, `asset_integrity` for hashes/dimensions/metadata, `animation_resource` for SpriteFrames and AnimatedSprite2D wiring, `tileset_resource` for TileSet layout/terrain wiring, `visual` for appearance/layout, and `experience` for subjective pacing/readability. State, flow, and resource behavior pass only with fresh structured `KECO_EVAL` evidence. Visual and experience checks may remain `manual_required`; do not turn screenshots, file parsing, or agent judgment into objective runtime proof.

After repair, rerun the failed evaluation and every affected regression. Keep the acceptance criteria fixed. A report may be `passed` only when every required evaluation has direct computed assertion evidence from a fresh run and current build/snapshot hashes; otherwise use `partial`, `failed`, or `blocked_before_write`. Aggregate report status is recomputed from assertion results; self-reported runtime status never overrides them. Legacy reports remain readable, but insufficient semantic evidence is `unknown` or `manual_required`, never an inferred pass.

`EvalReport.runtimeBatches` records each bounded Godot runtime sequence with `batchId`, the exact `evaluationIds` it covers, `runtimeSequence: [run_project, get_debug_output, stop_project]`, and `splitReason`. The field is always present. A passed report covers every evaluation exactly once; a partial, failed, or blocked report records only batches that actually ran and may use an empty array. Prefer one aggregate batch; when more than one batch is necessary, every batch must state a non-empty isolation, input, or lifecycle reason.
